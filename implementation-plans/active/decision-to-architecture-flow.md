  unchanged criteria, but each new run needs a documented diagnostic purpose and readiness

  not replace original blind validation. Preserve all spent attempts, no coaching or silent
  rerolls, and account for actual identity, input, tools, effects, and terminal capture.

## Scope and live test gates

This continuation covers only the shared-skill flow, its affected templates/consumers, frozen
forward-test fixtures and assessments, the plan, and coupled brief links. It authorizes no Git
staging, commit, push, unrelated repository change, or architecture record for the shared-skill
workflow. Preserve unrelated working-tree changes and every historical failure.

The active plan **incorporates the still-binding launch, side-effect, scoring, and preservation
contract** in the [historical D18/D22 test section](../history/decision-to-architecture-flow-pre-condensation.md#test-responsibilities-and-acceptance-contract)
and the [D24 continuation](../history/decision-to-architecture-flow-pre-condensation.md#prior-d24-authorization-and-completed-validation-batch).
D24 supersedes the old single-attempt ceilings, fixed historical-source baseline, and original
Sonnet/Terra launch routing only where that section says so. It does not supersede the content
criteria, independent reviews, or effect limits. For any new task: use a fresh original-equivalent
fixture and frozen actual sources/prompt/criteria; verify model, effort, workspace, injected
instructions and tool catalog before work; retain complete native calls/results and terminal
evidence. Use normal individual approvals, no permission bypass or global-configuration edit.
The test subject may not use an advisor, subagent, helper, Git mutation, withheld answer, or
out-of-fixture write; classify every read, command, write, and runtime/client effect. A missing
mandatory input or unclassified effect is `UNVERIFIED`, never PASS. Sequential attempts and
source drift follow the reviewed batch contract; do not silently substitute a model or route.
Correct a skill only for an authenticated defect or an explicitly authorized, independently
reviewed experiment, then revalidate affected controls before another live run. Neither an
author's semantic reading nor a mechanical reader silently upgrades the other's result.
